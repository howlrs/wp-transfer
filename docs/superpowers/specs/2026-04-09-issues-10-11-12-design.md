# Issues #10, #11, #12 — 統合設計

**日付:** 2026-04-09
**対象:** Gutenberg パーサー edge case / Yoast・ACF 実運用強化 / 生成コード品質
**レビュー:** Gemini Pro (deep) レビュー済み

## Issue #10: Gutenberg パーサー edge case

### 10-1. ネストリスト構造

**現状:** `extractListItems()` が `<li>` を正規表現でフラット抽出。ネストが壊れる。

**設計:** `node-html-parser` (軽量DOMパーサー、外部依存0) を analyzer パッケージに追加。`extractListItems()` を DOM ベースの再帰ウォーカーに置換。`<li>` 内の `<ul>`/`<ol>` を検出し、PT の `level` プロパティで深さを表現。

**理由:** 正規表現ベースの再帰は ReDoS リスクがある (Gemini 指摘)。DOM パーサーならエッジケースに強く、メンテコスト低。

### 10-2. `<br>` タグ処理

**現状:** `parseInlineHtml()` で `<br>` が未処理。タグ文字列がそのまま出力。

**設計:** `parseInlineHtml()` のトークナイザで `<br>` / `<br/>` / `<br />` を検出し、`\n` テキストスパンとして分割。

### 10-3. HTML エンティティ完全デコード

**現状:** 5 エンティティのみ (`&amp;` `&lt;` `&gt;` `&quot;` `&#39;`)

**設計:**
- 数値参照 `&#NNN;` と `&#xHHH;` を `String.fromCodePoint()` で汎用デコード
- 名前付きエンティティ 20 個追加: `&nbsp;` `&mdash;` `&ndash;` `&lsquo;` `&rsquo;` `&ldquo;` `&rdquo;` `&hellip;` `&copy;` `&reg;` `&trade;` `&times;` `&divide;` `&bull;` `&middot;` `&ensp;` `&emsp;` `&thinsp;` `&zwj;` `&zwnj;`
- 未知の名前付きエンティティはデコードせずそのまま出力 (フォールバック)

### 10-4. ブロック間 freeform HTML 保持

**現状:** Gutenberg ブロックとクラシック HTML 混在時、ブロック間の HTML がドロップ。

**設計:** `convertBlocksToPortableText()` で `name === "freeform"` を `htmlBlock` として変換。gutenberg-parser は既に freeform フォールバック出力済みなので converter 側のみ。

### 10-5. Reusable Block / Group Block

**設計:**
- `wp:block` (Reusable): `ref` 属性を保持した `referenceBlock` として PT 出力。実際の展開はランタイム側の責務。WXR に実体がある場合でも参照として扱う。
- `wp:group` (Group): `innerHTML` を再帰的に `parseGutenbergBlocks()` → `convertBlocksToPortableText()` してネスト展開。

## Issue #11: Yoast/ACF 実運用強化

### 11-1. Yoast プレースホルダー拡充

**現状:** 4 変数のみ (`%%title%%`, `%%sep%%`, `%%sitename%%`, `%%primary_category%%`)

**設計:** `YoastPlaceholderContext` を拡張:
- 追加フィールド: `author?`, `date?`, `modified?`, `excerpt?`, `categoryTitle?`
- 追加マッピング: `%%author%%`, `%%date%%`, `%%modified%%`, `%%excerpt%%`, `%%category_title%%`
- `%%page%%` と `%%focuskw%%` はコンテキスト依存のため、テンプレートリテラルの TODO コメントとして出力

### 11-2. ACF Repeater / Flexible Content

**現状:** スカラー値のみ。`inferredType === "json"` は `z.unknown()`。

**設計:** `generateAcfTemplate()` に型推論ロジック追加:
- サンプル値が配列 → `z.array(z.object({...}))` (Repeater)
- サンプル値がオブジェクト配列で type 判別キーあり → discriminated union (Flexible Content)
- サンプル値が文字列配列 → `z.array(z.string())` (Gallery)
- フォールバック: `z.unknown()` (既存動作維持)
- 生成コードに `// TODO: Verify inferred schema — auto-detected from sample data` コメント付与

### 11-3. 大規模サイト対応

**現状:** 全投稿を単一 JSON ファイルとしてインポート。

**設計:** 投稿数閾値 100 を設定:
- 100 件以下: 現行の静的 JSON 方式 (単一ファイル)
- 100 件超: ファイル分割方式 (1 投稿 = 1 JSON ファイル in `content/posts/`)
  - `getAllPosts()` は `fs.readdirSync` + 遅延読み込み
  - `getPostBySlug()` は単一ファイル読み込み
  - ビルド時メモリ削減、ISR 不要でシンプル

**理由:** ISR 切り替えは 2 パターンの scaffold 生成が必要で複雑すぎる (Gemini 推奨)。

### 11-4. Rank Math 対応

**設計:** `extractYoastMeta()` を `extractSeoMeta()` にリネーム。`rank_math_*` プレフィックスのメタキーも同じ型 (`SeoMeta`) にマッピング。型エイリアス `YoastMeta = SeoMeta` を残して後方互換維持。

影響: 内部使用のみ (CLI + analyzer)。TypeScript 型エラーで全箇所検出可能。

## Issue #12: 生成コード品質

### 12-1. in-place sort 修正

**設計:** `generateContentDataLayer()` 内の `.sort()` → `[...posts].sort()` に変更。

### 12-2. renderSpan XSS 修正

**設計:**
- `renderSpan()` をテンプレートリテラル + `dangerouslySetInnerHTML` から React 要素ベースに変更
- マーク適用: `<strong>` / `<em>` / `<code>` / `<a>` の React 要素でラップ
- `htmlBlock` は引き続き `dangerouslySetInnerHTML` だが、`isomorphic-dompurify` の import + サニタイズコードを生成に追加

### 12-3. 空カテゴリ表示

**設計:** `notFound()` → 「No posts in this category yet.」メッセージ表示に変更。カテゴリ自体が存在しない場合のみ `notFound()`。

### 12-4. remotePatterns プロトコル自動判定

**設計:** デフォルト HTTPS 固定。`siteUrl` が `http://` の場合のみ、コメント付きで HTTP パターンも追加 (`// WARNING: HTTP — consider migrating to HTTPS`)。

1. **#12** (生成コード品質) — バグ修正、依存関係なし、即効性
