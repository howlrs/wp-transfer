# WP移行ツール完成 — UI忠実再現 + E2Eテスト + CLIワークフロー洗練

## 背景

wp-transferのanalyze-phpは業務ロジック移行済みだが、生成されるNext.js管理画面のUI/UXが不十分。
移行元WPカスタム管理画面のデザインを忠実に再現し、E2Eテストで検証し、CLIワークフローを一気通貫で磨く。

## ゴール

1. client-a案件が本番運用可能なUI品質
2. analyze-php → run の一気通貫が次案件にも即適用可能
3. 22スクリプト対応のE2Eテストで移行完了を証明

---

## Phase 1: WP管理画面UI忠実再現

### 現状
- `admin-scaffold-generator.ts` (1617行) がinline style (`fw="plain"`) で生成
- 色はモダンUI風（#2563eb青系）でWP管理画面と乖離
- 不足: 通知バー、バリデーションフィードバック、ローディング状態、モーダル、ページネーション

### 方針
PHPテンプレートのHTML構造・CSSクラスを解析し、生成テンプレートにWP管理画面スタイルを反映する。

### 実装項目

#### 1-1. WP Admin CSSテーマ生成
- `admin-scaffold-generator.ts` に WP管理画面カラーパレット適用
  - サイドバー: `#23282d` (WPダーク)
  - プライマリ: `#0073aa` (WP青)
  - ホバー: `#006799`
  - アクセント: `#00a0d2`
  - 通知: success `#46b450`, warning `#ffb900`, error `#dc3232`
- グローバルCSS生成 (`globals.css`) をadmin-scaffold-generatorに追加
- WPのbox-sizing, font-family (`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto`), line-height再現

#### 1-2. 管理画面レイアウト改善
- サイドバー: WP風メニュー（アイコン + ラベル、アクティブ状態、サブメニュー展開）
- ヘッダーバー: ページタイトル + アクションボタン（WPの「新規追加」パターン）
- コンテンツ: `.wrap` スタイルのパディング・マージン

#### 1-3. フォームUI改善
- フィールドレイアウト: label上、input下のWPパターン
- バリデーション: フィールド横に赤テキスト、送信時のサマリー
- ローディング: 送信ボタンのスピナー + disabled
- 成功/エラー通知: WP `.notice` スタイル（ページ上部の帯）
- select/textarea/file: 既存formSpec生成にスタイル追加

#### 1-4. テーブル（一覧）UI改善
- WP `.wp-list-table` スタイル: ストライプ行、ホバーハイライト
- ページネーション: 件数表示 + ページ送り
- ソートヘッダー: クリック可能カラムヘッダー
- 一括操作: チェックボックス + アクションドロップダウン（バルクアクション）

#### 1-5. 共通コンポーネント生成
admin-scaffold-generatorが以下のReactコンポーネントを `components/admin/` に生成:
- `AdminLayout.tsx` — サイドバー + ヘッダー + コンテンツ
- `AdminNotice.tsx` — success/warning/error通知
- `DataTable.tsx` — ソート・ページネーション付きテーブル
- `FormField.tsx` — ラベル + input + バリデーションメッセージ
- `LoadingButton.tsx` — スピナー付き送信ボタン

### 検証基準
- 生成された管理画面をWP管理画面と並べて視覚比較し、レイアウト・色・操作感が同等
- 全フォームでバリデーションフィードバック・ローディング状態が動作

## Phase 2: E2Eテスト (#42)

### 方針
Issue #42のコメントで決定済みの4フェーズ戦略に従う。

### 実装項目

#### 2-1. テストインフラ整備
- `verify-generator.ts` を拡張し、PHPスクリプト分析結果から22スクリプト対応のAPIテストを生成
- Docker上のNext.jsアプリに対するHTTPリクエスト + レスポンスボディ検証
- テストヘルパー: 認証トークン取得、テストデータ作成/クリーンアップ

#### 2-2. Phase 1: 認証保護テスト
- 未認証リダイレクト確認
- 権限チェック（admin/user権限分離）

#### 2-3. Phase 2: 全API正常系CRUD (22スクリプト)
- Domain 1: イベント管理 (7スクリプト) — 作成/更新/複製/停止/復元/削除
- Domain 2: スロット管理 (3スクリプト) — 作成/更新/削除
- Domain 3: お知らせ管理 (8スクリプト) — 作成/更新/テキストON-OFF/バナーON-OFF
- Domain 4: 抽選管理 (1スクリプト) — 無効化
- Domain 5: ユーザー管理 (2スクリプト) — ブラックリストON-OFF

#### 2-4. Phase 3: 異常系 + バリデーション
- 不正入力（必須フィールド欠落、型不正）
- 存在しないリソースへの操作（404）
- 状態遷移の整合性（停止済みイベントの再停止等）

#### 2-5. Phase 4: Playwright E2E
- ログイン → イベント作成 → 一覧確認 → 編集 → 削除のクリティカルパス
- ファイルアップロード動作確認

### 検証基準
- 22スクリプト全てに対応するテストケースが存在
- Docker環境で `pnpm --filter wp-transfer-cli dev run <project>` で全テストパス

## Phase 3: CLIワークフロー洗練

### 実装項目

#### 3-1. analyze-phpの出力品質改善
- Phase 1のUI改善テンプレートをデフォルトに統合
- 生成ファイル一覧のサマリー改善（カテゴリ別件数）
- 未対応PHP機能の警告出力

#### 3-2. runコマンドの改善
- テスト結果サマリー: パス/フェイル件数 + 失敗テスト名
- 移行カバレッジレポート: PHPスクリプト数 vs テスト対応数
- HTML/Markdownレポート自動生成

#### 3-3. エラーリカバリー
- Docker起動失敗時のガイダンス（ポート競合、メモリ不足等）
- Prismaマイグレーション失敗時のロールバック手順出力
- よくあるエラーパターンの自動診断

#### 3-4. 汎用化
- WPテーマ固有のformSpec解析をプラグイン化（client-a固有ロジックの分離）
- 設定ファイル (`wp-transfer.config.json`) でテーマ・スタイル・テスト戦略のカスタマイズ

### 検証基準
- 新しいPHPプロジェクトに対して analyze-php → run が一発で完走
- エラー時に具体的なリカバリー手順が表示される
- 移行カバレッジレポートが移行完了判定の根拠として使える
